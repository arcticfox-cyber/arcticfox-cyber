# Contributing to Arctic Fox

Thank you for considering a contribution.

## Before you start

1. Read the README and the license of the specific repository.
2. Check existing issues and pull requests to avoid duplicate work.
3. For substantial changes, open an issue first to discuss the proposed approach.
4. Never submit credentials, API keys, personal data, or private targets.

## Development workflow

1. Fork the repository and create a focused branch.
2. Keep changes small and explain the reason for each meaningful change.
3. Follow the project's existing language, formatting, and dependency conventions.
4. Run the available tests, linters, and relevant checks before submitting.
5. Update documentation when behavior, setup, or commands change.

## Pull requests

Include:
- A clear summary of the problem and solution.
- Steps to reproduce or verify the change.
- Test results, including any checks you could not run.
- Screenshots or terminal output when they materially clarify a UI or CLI change.

Be respectful, constructive, and open to review feedback.

## Security and responsible use

Contributions must support lawful, authorized security work. Do not include exploit instructions targeting real systems without permission, malware, credential theft, stealth, persistence, or unauthorized access. Report suspected vulnerabilities privately using the instructions in SECURITY.md rather than publishing exploit details in an issue.

## Project-specific rules

This profile repository provides general guidance. Each project may have additional setup, testing, licensing, and contribution requirements; those repository-specific instructions take precedence.
