# Security Policy

## Supported projects

Security support and maintenance status may differ between repositories. Check the individual project's README and release history before relying on it.

## Reporting a vulnerability

Please do not publish exploitable vulnerability details, credentials, personal information, or proof-of-concept payloads in a public issue.

Use GitHub's **Report a vulnerability** feature on the affected repository when private vulnerability reporting is available. Include:
- The affected repository, version, and commit (if known).
- A concise description and potential impact.
- Reproduction steps in a local lab or other environment you are authorized to test.
- Any suggested mitigation.

If private reporting is unavailable, contact the maintainer through the contact method listed on the GitHub profile and ask for a private security-reporting channel. Do not send secrets or sensitive data in a public discussion.

## Responsible use

All tools and research are intended for education, defensive work, and explicitly authorized security testing. Obtain permission before testing systems, networks, accounts, or applications you do not own.
